⏰ Sistema de tareas programadas (launchd)

Todas las tareas programadas (excepto inbox.py) corren via launchd en macOS, no desde Claude Code. Esto significa que el app de Claude Code no necesita estar abierto — la Mac solo tiene que estar prendida y logueada. Cada tarea es un par script + plist.

🗂 Estructura de archivos
  • Wrapper genérico: ~/.local/bin/run-claude-task.sh <task-name> [model] — usado por casi todas las tareas, levanta claude --model X --permission-mode bypassPermissions -p "Execute the <task-name> scheduled task by following ~/.claude/scheduled-tasks/<task-name>/SKILL.md exactly".
  • Wrappers especializados: ~/.local/bin/run-onmexico.sh, ~/.local/bin/run-dailyt.sh, ~/.local/bin/run-scant.sh — tienen lógica adicional (sentinel, transcript check, retries).
  • Plists: ~/Library/LaunchAgents/com.resisres.<task-name>.plist — definen el horario via StartCalendarInterval y los args al wrapper.
  • Logs: ~/.local/share/<task-name>/.<task-name>-launchd.log y stdout.log / stderr.log.
  • Notificación de errores: si una tarea falla, manda alerta al DM privado del bot (chat_id 6855761084).

Autenticación

El CLI claude que corre desde launchd usa la misma cuenta que la app de Claude Code (suscripción, no API). Para que funcione desde launchd hay que loguearse explícitamente desde Terminal con claude /login al menos una vez — esto guarda credenciales accesibles al CLI standalone, separadas del Keychain de la app. Si en algún momento las tareas empiezan a fallar con "Not logged in", repetí ese login desde Terminal.

Cómo agregar/editar/desactivar una tarea

No editar plists a mano salvo cuando sea necesario. La forma normal es decirle a Claude Code en lenguaje natural: "cambia el horario de scant a las 8 PM", "crea una tarea nueva que corra X cada lunes", "desactiva mananera-datos". Claude conoce los paths y formatos.

Si querés hacerlo manualmente:

  • Listar: launchctl list | grep resisres
  • Disparar manualmente: launchctl start com.resisres.<name>
  • Recargar después de editar el plist: launchctl unload ~/Library/LaunchAgents/com.resisres.<name>.plist && launchctl load ~/Library/LaunchAgents/com.resisres.<name>.plist
  • Ver log: cat ~/.local/share/<name>/.<name>-launchd.log

Por qué fuera de Google Drive: macOS TCC restringe lectura de carpetas de iCloud/GoogleDrive. Procesos lanzados por launchd no heredan permisos del Terminal, y un binario nuevo (ej: después de un upgrade de Homebrew Python) no tiene entrada en la base TCC → "Operation not permitted". Manteniendo el script en ~/scripts/inbox/ el problema desaparece para siempre. Los docs en htmls/inbox/ son leídos por el binario claude, que sí tiene permiso TCC propio.

Cómo funciona

Cada mensaje de Telegram se pasa a una sesión persistente de Claude Code (claude --resume <session-id>). La sesión lee LEEME.html e INBOX_SYSTEM.md al inicio y mantiene contexto completo — puede hacer edits, responder preguntas, ejecutar comandos, todo sin routing ni modos separados. Las sesiones expiran después de 6 horas de inactividad.

Setup en nueva máquina

📦 Dependencias y configuración
  1. Crear virtualenv: python3 -m venv ~/inbox-venv (apunta el symlink interno a /usr/local/opt/python@3.14/bin/python3.14 para que sobreviva upgrades de Homebrew)
  2. Instalar deps: ~/inbox-venv/bin/pip install requests
  3. Crear carpeta local del bot: mkdir -p ~/scripts/inbox y copiar inbox-v2.py, .api-key, .inbox-v2-state.json, INBOX_SYSTEM.md ahí (FUERA de Google Drive — ver TCC arriba)
  4. Loguearse en Claude CLI: claude /login desde Terminal
  5. Setup SSH key para git push: ssh-keygen -t ed25519 y agregar la public key a GitHub
  6. Cambiar remote a SSH: git -C /tmp/sds remote set-url origin git@github.com:sartinezmelgarejo-eng/sds.git
  7. El plist debe incluir SoftResourceLimits → NumberOfFiles → 65536 (default launchd de 256 no le alcanza a Claude CLI)
  8. Cargar el plist: launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.resisres.inbox.plist

Debugging

  • Ver log: cat ~/inbox.log y cat ~/inbox-error.log
  • Correr manualmente: ~/inbox-venv/bin/python3 -u ~/scripts/inbox/inbox-v2.py
  • Disparar via launchd: launchctl kickstart -k gui/$UID/com.resisres.inbox
  • Recargar plist (después de editar): launchctl bootout gui/$UID/com.resisres.inbox; launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.resisres.inbox.plist
  • Ver state: cat ~/scripts/inbox/.inbox-v2-state.json
  • Resetear sesión (forzar sesión nueva): poner session_id: null en el state file

Es el archivo más complejo y el que más se actualiza. Single-file React app con Babel transpilation en el navegador.

📖 Cómo agregar un libro nuevo

Paso a paso para no romper nada:

1. Preparar el archivo

Pon el PDF o EPUB en Books/, dentro de una subcarpeta del autor (ej: Books/Marx/Nuevo-Libro.pdf). Si el autor ya tiene carpeta, úsala. Si no, crea una con el formato Nombre-Apellido.

2. Decidir el formato

Usa el formato expandido (multi-línea) — es el estándar y el más legible. El formato compacto existe por herencia pero no se recomienda para libros nuevos. Ejemplo mínimo:

{ id: "miid", estante: "mexico-profundo", // o: transformaciones, economia-poder, fundamentos, revoluciones, filosofia coverId: "miid", filePath: "Autor/Archivo.pdf", title: "Título del Libro", author: "Nombre del Autor", year: "2020", desc: "Descripción breve del libro.", tesis: "Tesis principal.", ideas: ["Idea 1", "Idea 2", "Idea 3"], contexto: "Contexto histórico.", porqueLeer: "Por qué importa este libro.", conexiones: ["otroid1", "otroid2"], tags: ["tag1", "tag2"], quotes: [ { text: "Texto exacto de la cita tal cual aparece en el PDF.", page: "p.45" } ] }

3. Agregar al array books

Busca const books = [ en el HTML (~línea 2710). Agrega el objeto nuevo al final, antes del cierre ];. No olvides la coma después del libro anterior. El id debe ser único — usa minúsculas sin espacios ni acentos (ej: "dusseletica", "marxcapital1").

4. Agregar entrada a QUOTE_PAGES (opcional pero recomendado)

Si el libro tiene citas y el PDF tiene texto extraíble, busca la cita en el PDF para obtener la página física. Agrega al objeto QUOTE_PAGES (línea ~2685):

// formato: "bookId::quoteIndex": páginaFísicaDelPDF "miid::0": 45, // primera cita del libro, página 45 "miid::1": 112 // segunda cita, página 112

5. Validar

Extraer el bloque <script> y correr node --check. Si falla, hay un error de sintaxis — revisar comas, comillas, y llaves. Este paso es obligatorio antes de guardar.

📝 Cómo agregar o verificar citas

La calidad de las citas es lo más importante. Estas son las lecciones aprendidas:

Extraer texto del PDF

Usar pdfplumber (Python) para extraer texto. Ejemplo:

import pdfplumber with pdfplumber.open("Books/Autor/Libro.pdf") as pdf: for i, page in enumerate(pdf.pages): text = page.extract_text() if text and "fragmento de la cita" in text: print(f"Página {i+1}: encontrado")

El número de página en QUOTE_PAGES es la página física del PDF (la que muestra el lector), no la numeración impresa del libro. pdfplumber empieza en 0, así que page[41] corresponde a la página 42 del PDF.

Criterios de calidad para citas

Una buena cita cumple todos estos criterios:

  • Es una oración o párrafo completo con sentido propio (no un fragmento cortado).
  • Expresa una idea sustancial del libro — no es un encabezado, título de capítulo, dato bibliográfico, ni dedicatoria.
  • Tiene entre 20 y 200 palabras aproximadamente — ni tan corta que no diga nada, ni tan larga que abrume.
  • Es legible (no es OCR basura con caracteres rotos).
  • No es una cita que el autor hace de otro autor (a menos que sea particularmente notable).

Errores comunes que evitar

  • Citas del índice o tabla de contenido — parecen texto pero son solo encabezados con números de página.
  • Información editorial — "Primera edición, 1975. ISBN..." no es una cita.
  • Texto garbled de OCR — si ves "lvi est0 es un t3xto", el PDF es imagen y no sirve para extraer citas automáticamente.
  • Páginas estimadas — nunca calcular la página por offset. Los PDFs tienen portadas, prólogos, páginas en blanco. Siempre buscar el texto exacto.
  • Comillas dentro de la cita — si la cita contiene comillas dobles ("), hay que escaparlas en el JS como \", o usar comillas simples en el string del array.

PDFs escaneados (imágenes)

Algunos PDFs son imágenes sin texto extraíble. pdfplumber devolverá cadenas vacías o basura. Para estos libros, las citas se pueden agregar manualmente (copiando del libro físico o de otra fuente verificada), pero no se agrega entrada a QUOTE_PAGES — el link "Ver en PDF" no serviría porque el visor no puede navegar a texto dentro de una imagen.
