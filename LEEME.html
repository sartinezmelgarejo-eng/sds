📱 PWA y GitHub Pages

Todos los HTMLs son Progressive Web Apps (PWA) — se pueden instalar como apps en Android/Huawei desde el navegador (Chrome → "Añadir a pantalla de inicio"). Abren en pantalla completa sin barra de Chrome.

Cada app tiene su propio manifest en pwa/manifest-{nombre}.json con nombre, icono, y colores propios. El service worker (pwa/sw.js) usa estrategia network-first y cachea los CDNs de React/Recharts/Babel.

GitHub Pages — Todo se despliega en sartinezmelgarejo-eng.github.io/sds/. El repo es público (sartinezmelgarejo-eng/sds, branch gh-pages). Las tareas programadas hacen push automáticamente después de cada actualización. El directorio local de deploy es /tmp/sds.

⏰ Sistema de tareas programadas (launchd)

Todas las tareas programadas (excepto inbox.py) corren via launchd en macOS, no desde Claude Code. Esto significa que el app de Claude Code no necesita estar abierto — la Mac solo tiene que estar prendida y logueada. Cada tarea es un par script + plist.

🗂 Estructura de archivos
  • Wrapper genérico: ~/.local/bin/run-claude-task.sh <task-name> [model] — usado por casi todas las tareas, levanta claude --model X --permission-mode bypassPermissions -p "Execute the <task-name> scheduled task by following ~/.claude/scheduled-tasks/<task-name>/SKILL.md exactly".
  • Wrappers especializados: ~/.local/bin/run-onmexico.sh, ~/.local/bin/run-dailyt.sh, ~/.local/bin/run-scant.sh — tienen lógica adicional (sentinel, transcript check, retries).
  • Plists: ~/Library/LaunchAgents/com.resisres.<task-name>.plist — definen el horario via StartCalendarInterval y los args al wrapper.
  • Logs: ~/.local/share/<task-name>/.<task-name>-launchd.log y stdout.log / stderr.log.
  • Notificación de errores: si una tarea falla, manda alerta al DM privado del bot (chat_id 6855761084).

Autenticación

El CLI claude que corre desde launchd usa la misma cuenta que la app de Claude Code (suscripción, no API). Para que funcione desde launchd hay que loguearse explícitamente desde Terminal con claude /login al menos una vez — esto guarda credenciales accesibles al CLI standalone, separadas del Keychain de la app. Si en algún momento las tareas empiezan a fallar con "Not logged in", repetí ese login desde Terminal.

Cómo agregar/editar/desactivar una tarea

No editar plists a mano salvo cuando sea necesario. La forma normal es decirle a Claude Code en lenguaje natural: "cambia el horario de scant a las 8 PM", "crea una tarea nueva que corra X cada lunes", "desactiva mananera-datos". Claude conoce los paths y formatos.

Si querés hacerlo manualmente:

  • Listar: launchctl list | grep resisres
  • Disparar manualmente: launchctl start com.resisres.<name>
  • Recargar después de editar el plist: launchctl unload ~/Library/LaunchAgents/com.resisres.<name>.plist && launchctl load ~/Library/LaunchAgents/com.resisres.<name>.plist
  • Ver log: cat ~/.local/share/<name>/.<name>-launchd.log

📲 Sistema Inbox de Telegram

Sistema que permite enviar mensajes, imágenes y archivos HTML desde el teléfono al bot @Resisresbot y que Claude los procese automáticamente. Usa sesiones persistentes de Claude Code — cada mensaje se envía a una sesión con claude --resume que mantiene contexto completo entre turnos. Corre vía launchd (cada 5 min).

  • Credenciales WordPress: htmls/inbox/.wp-creds.json (site, username, app_password, user_id — gitignored, perms 600). Usadas para subir imágenes a mexicosolidarity.com Media Library vía REST API durante la traducción
  • Chat privado: TG_PRIVATE_CHAT_ID = 6855761084 (DM de Samuel con @Resisresbot)

Cómo funciona

Cada mensaje de Telegram se pasa a una sesión persistente de Claude Code (claude --resume <session-id>). La sesión lee LEEME.html e INBOX_SYSTEM.md al inicio y mantiene contexto completo — puede hacer edits, responder preguntas, ejecutar comandos, todo sin routing ni modos separados. Las sesiones expiran después de 6 horas de inactividad.

Diferencias con inbox v1 (inbox.py)

  • v1 usaba la API de Anthropic (Sonnet para routing/patches, Opus para free mode) — cada mensaje era stateless
  • v2 usa Claude Code CLI con sesiones persistentes — tiene memoria entre turnos, acceso a herramientas del sistema, y cero costo de API
  • v1 tenía modos explícitos (normal, free, question, command) — v2 entiende todo naturalmente por contexto
  • El viejo inbox.py sigue en la carpeta como referencia pero no está activo

Setup en nueva máquina

📦 Dependencias y configuración
  1. Crear virtualenv: python3 -m venv ~/inbox-venv
  2. Instalar deps: ~/inbox-venv/bin/pip install requests
  3. Loguearse en Claude CLI: claude /login desde Terminal
  4. Setup SSH key para git push: ssh-keygen -t ed25519 y agregar la public key a GitHub
  5. Cambiar remote a SSH: git -C /tmp/sds remote set-url origin git@github.com:sartinezmelgarejo-eng/sds.git
  6. Cargar el plist: launchctl load ~/Library/LaunchAgents/com.resisres.inbox.plist

Debugging

  • Ver log: cat ~/inbox.log y cat ~/inbox-error.log
  • Correr manualmente: ~/inbox-venv/bin/python3 -u "$HTMLS_DIR/inbox/inbox-v2.py"
  • Disparar via launchd: launchctl start com.resisres.inbox
  • Ver state: cat "$HTMLS_DIR/inbox/.inbox-v2-state.json"
  • Resetear sesión (forzar sesión nueva): poner session_id: null en el state file
  • Ver mensajes pendientes en Telegram: curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getUpdates"
  • Skipear mensajes viejos: editar .inbox-v2-state.json y poner offset alto
  • Ver status launchd: launchctl list | grep inbox
  • Lock fantasma: el lock vive en /tmp/inbox-v2.lock (FUERA de Google Drive para evitar deadlocks de FUSE). Si el inbox parece colgado, revisar: cat /tmp/inbox-v2.lock y ps -p $(cat /tmp/inbox-v2.lock). Si el PID está muerto, borrar el archivo.

Modos de autenticación de Claude CLI

El inbox usa Claude Code CLI con la suscripción del usuario. Si el login expira, hay un fallback automático a API key:

  1. Default: usa CLI con claude /login (suscripción, cero costo)
  2. Fallback automático: si claude devuelve "Not logged in", lee el API key desde $HTMLS_DIR/inbox/.api-key y reintenta. Te manda notificación al DM privado avisando del fallback (que consume créditos de API).

Si recibís ⚠️ CLI login expirado en el DM, hay que correr claude /login desde Terminal cuando puedas. Mientras tanto el fallback te mantiene funcionando.

  • Refinamiento: si Samuel responde al card en el topic ("cambia X por Y", "rehaz el primer párrafo"), edita article.html y meta.json directo, push, responde con un ✅ Editado: .... NO regeneres todo.

Template HTML del artículo

El HTML usa clases Gutenberg/Kadence (wp-block-*) sin CSS inline. WP convierte el HTML pegado en bloques nativos. Estructura básica:

🔧 Arquitectura técnica del MAPA

El MAPA es un solo archivo HTML (~1.3 MB) con CSS, JavaScript, y todos los datos embebidos. No hay servidor, no hay base de datos. Todo corre en el navegador.

Estructura de datos

Los libros están en un array const books = [...] que empieza alrededor de la línea 2710. Son 219 objetos con estas propiedades: id, estante, coverId, filePath, title, author, year, desc, tesis, ideas, contexto, porqueLeer, conexiones, tags, quotes. Hay dos formatos coexistiendo: 210 libros en formato expandido (multi-línea, una propiedad por línea) y 9 en formato compacto (todo en una línea). Cualquier script que modifique el array debe detectar ambos.

Las citas con link a página exacta viven en QUOTE_PAGES (línea ~2685), con la clave "bookId::quoteIndex" y el valor es el número de página física del PDF.

Funciones clave

getQuotePageLink(book, quoteText, quoteIndex) — Genera el link "📄 Ver en PDF" para una cita. Recibe el libro, el texto de la cita, y opcionalmente el índice. Si no recibe índice explícito, busca el texto en book.quotes para encontrarlo. Devuelve cadena vacía en móvil o si no hay entrada en QUOTE_PAGES.

getFileButtonHTML(book) — Genera el botón "📂 Abrir archivo". Devuelve cadena vacía en móvil.

normalizeSearch(str) — Quita acentos para búsqueda: normaliza a NFD y elimina caracteres combinantes. Así "mexico" encuentra "México".

IS_MOBILE — Variable global que detecta Android, iOS, Huawei, HarmonyOS, o ancho ≤768px. Controla qué elementos se muestran.

Las 4 vistas principales

El MAPA tiene 4 vistas: Estantes (libros agrupados por tema), Explorador (detalle de un libro con citas y conexiones), Línea de tiempo (cronología con citas destacadas), y Atlas de conceptos (mapa visual de ideas con citas aleatorias). Cada una llama a getQuotePageLink de manera diferente — en Estantes pasa índice 0, en Explorador pasa el idx del map, y en Atlas/Timeline pasa solo el texto para que la función busque el índice.

📊 Arquitectura técnica de monitoring.html

Es el archivo más complejo y el que más se actualiza. Single-file React app con Babel transpilation en el navegador.

Stack

React 18 + Recharts + Babel standalone, todo desde CDN. Sin build, sin servidor. El HTML tiene un solo <script type="text/babel"> con todo el código React.

Datos

Todos los datos están embebidos como constantes al inicio del script. El array UPDATES contiene las actualizaciones recientes con fecha, fuente, texto, tag, y gráficas relacionadas (rel). Las gráficas se definen como objetos con id, t (título), th (tema), s (fuente), d (descripción), r (función render). Hay ~100 gráficas organizadas en 7 categorías/temas: w (trabajo), r (bienestar), s (seguridad), e (economía), f (fiscal), n (energía), d (desarrollo).

Responsive

Usa cols state (1-5 columnas según ancho de ventana). _isMob() función fuera del componente para estilos de márgenes y ejes. Patrones Proxy/getter para que mg (margins), ax (axis tick style), lgS (legend style) se recalculen en cada render. yH reduce el ancho del YAxis a 25px en móvil.

Modos

Monitor: Slots rotatorios con auto-advance (30s escalonado). Cada slot muestra 1-3 gráficas que rotan. Barra UPDATES arriba con swipe en móvil.

Explorar: Navegación libre. Filtro por categoría (dropdown en móvil, botones en desktop), ordenar por recientes, drill-down con gráficas de pie interactivas. En desktop las gráficas se agrupan por categoría en filas.

Cómo agregar datos

Las tareas programadas actualizan los datos automáticamente. Cada tarea: (1) lee monitoring.html, (2) busca/actualiza las constantes de datos relevantes, (3) agrega entrada a UPDATES con la fecha y fuente, (4) guarda, (5) hace backup, (6) push a GitHub Pages. Regla importante: un entry de UPDATES por cada cambio individual, nunca combinar múltiples indicadores en uno solo.

📖 Cómo agregar un libro nuevo

Paso a paso para no romper nada:

1. Preparar el archivo

Pon el PDF o EPUB en Books/, dentro de una subcarpeta del autor (ej: Books/Marx/Nuevo-Libro.pdf). Si el autor ya tiene carpeta, úsala. Si no, crea una con el formato Nombre-Apellido.

2. Decidir el formato

Usa el formato expandido (multi-línea) — es el estándar y el más legible. El formato compacto existe por herencia pero no se recomienda para libros nuevos. Ejemplo mínimo:

{ id: "miid", estante: "mexico-profundo", // o: transformaciones, economia-poder, fundamentos, revoluciones, filosofia coverId: "miid", filePath: "Autor/Archivo.pdf", title: "Título del Libro", author: "Nombre del Autor", year: "2020", desc: "Descripción breve del libro.", tesis: "Tesis principal.", ideas: ["Idea 1", "Idea 2", "Idea 3"], contexto: "Contexto histórico.", porqueLeer: "Por qué importa este libro.", conexiones: ["otroid1", "otroid2"], tags: ["tag1", "tag2"], quotes: [ { text: "Texto exacto de la cita tal cual aparece en el PDF.", page: "p.45" } ] }

3. Agregar al array books

Busca const books = [ en el HTML (~línea 2710). Agrega el objeto nuevo al final, antes del cierre ];. No olvides la coma después del libro anterior. El id debe ser único — usa minúsculas sin espacios ni acentos (ej: "dusseletica", "marxcapital1").

4. Agregar entrada a QUOTE_PAGES (opcional pero recomendado)

Si el libro tiene citas y el PDF tiene texto extraíble, busca la cita en el PDF para obtener la página física. Agrega al objeto QUOTE_PAGES (línea ~2685):

// formato: "bookId::quoteIndex": páginaFísicaDelPDF "miid::0": 45, // primera cita del libro, página 45 "miid::1": 112 // segunda cita, página 112

5. Validar

Extraer el bloque <script> y correr node --check. Si falla, hay un error de sintaxis — revisar comas, comillas, y llaves. Este paso es obligatorio antes de guardar.

📝 Cómo agregar o verificar citas

La calidad de las citas es lo más importante. Estas son las lecciones aprendidas:

Extraer texto del PDF

Usar pdfplumber (Python) para extraer texto. Ejemplo:

import pdfplumber with pdfplumber.open("Books/Autor/Libro.pdf") as pdf: for i, page in enumerate(pdf.pages): text = page.extract_text() if text and "fragmento de la cita" in text: print(f"Página {i+1}: encontrado")

El número de página en QUOTE_PAGES es la página física del PDF (la que muestra el lector), no la numeración impresa del libro. pdfplumber empieza en 0, así que page[41] corresponde a la página 42 del PDF.

Criterios de calidad para citas

Una buena cita cumple todos estos criterios:

  • Es una oración o párrafo completo con sentido propio (no un fragmento cortado).
  • Expresa una idea sustancial del libro — no es un encabezado, título de capítulo, dato bibliográfico, ni dedicatoria.
  • Tiene entre 20 y 200 palabras aproximadamente — ni tan corta que no diga nada, ni tan larga que abrume.
  • Es legible (no es OCR basura con caracteres rotos).
  • No es una cita que el autor hace de otro autor (a menos que sea particularmente notable).

Errores comunes que evitar

  • Citas del índice o tabla de contenido — parecen texto pero son solo encabezados con números de página.
  • Información editorial — "Primera edición, 1975. ISBN..." no es una cita.
  • Texto garbled de OCR — si ves "lvi est0 es un t3xto", el PDF es imagen y no sirve para extraer citas automáticamente.
  • Páginas estimadas — nunca calcular la página por offset. Los PDFs tienen portadas, prólogos, páginas en blanco. Siempre buscar el texto exacto.
  • Comillas dentro de la cita — si la cita contiene comillas dobles ("), hay que escaparlas en el JS como \", o usar comillas simples en el string del array.

PDFs escaneados (imágenes)

Algunos PDFs son imágenes sin texto extraíble. pdfplumber devolverá cadenas vacías o basura. Para estos libros, las citas se pueden agregar manualmente (copiando del libro físico o de otra fuente verificada), pero no se agrega entrada a QUOTE_PAGES — el link "Ver en PDF" no serviría porque el visor no puede navegar a texto dentro de una imagen.
