⚖️ Reglas (para humanos y para Claude)

Este documento es la fuente de verdad para cualquier persona o sesión de IA que trabaje con estos archivos. Si estás leyendo esto desde Claude, Cowork, o cualquier otro asistente: sigue estas reglas antes de tocar nada.

Regla 1 — No inventar datos

Nunca agregar citas, páginas, o información que no venga directamente del PDF o del texto original. Si no se puede verificar una página exacta (por ejemplo en un PDF escaneado), es mejor dejarlo sin link que poner una página falsa. Lo mismo aplica para descripciones, tesis, o contextos históricos: si no estás seguro, pregunta.

Regla 2 — No romper el archivo

El MAPA es un archivo HTML de 8600+ líneas con JavaScript embebido. Una coma fuera de lugar lo mata. Antes de guardar cualquier cambio, siempre validar la sintaxis con node --check extrayendo el bloque <script>. Si no pasa el check, no se guarda. Sin excepciones.

Regla 3 — Siempre hacer respaldo

Antes de cualquier modificación significativa al MAPA, crear una copia con sufijo descriptivo (ej: .pre-quotes-backup). Los respaldos se pueden limpiar después, pero nunca antes de verificar que todo funciona.

Regla 4 — No mover ni renombrar archivos en Books/

El MAPA tiene las rutas exactas de cada PDF/EPUB (ej: Marx/El-Capital-Vol1.pdf). Si renombras una carpeta o archivo en Books/, el botón "Abrir archivo" deja de funcionar. Si necesitas reorganizar, hay que actualizar también el filePath correspondiente en el MAPA.

Regla 5 — Los dos formatos de libros

Hay 210 libros en formato expandido (multi-línea) y 9 en formato compacto (una sola línea con todas las propiedades). Los scripts que modifican el array books deben detectar ambos formatos. Esto ya causó un bug grave — no asumir que todos los libros tienen el mismo formato.

Regla 6 — QUOTE_PAGES solo con páginas verificadas

El objeto QUOTE_PAGES mapea citas a páginas exactas del PDF. Solo agregar entradas cuando la página fue encontrada buscando el texto exacto de la cita en el PDF con una herramienta como pdfplumber o pdftotext. Nunca calcular páginas por offset o estimación — los libros tienen introducciones, prólogos, y numeración inconsistente.

Regla 7 — Reportar cambios en este documento

Cualquier modificación a los archivos que afecte algo documentado aquí — estructura, reglas, conexiones, conteos, o funcionalidad — debe reflejarse en este LEEME antes de terminar la sesión. Este documento es la fuente de verdad. Si no se actualiza, la siguiente sesión (humana o de IA) trabajará con información incorrecta. Sin excepciones.

Regla 8 — Orden en la carpeta htmls/

La carpeta htmls/ debe mantenerse organizada. Los archivos de respaldo (.backup, .bak, .pre-*-backup) van en una subcarpeta backups/, no sueltos junto a los archivos activos. Además, no debe haber más de 4 respaldos por documento — al crear un quinto, se elimina el más antiguo. Esto evita que la carpeta se llene de archivos muertos.

Este LEEME debe actualizarse cada vez que ocurra cualquiera de estas cosas:

  • Se agrega o elimina un archivo HTML en la carpeta — actualizar la sección "Los archivos" y el diagrama de estructura.

  • Se descubre un bug o una regla nueva — agregarla a la sección de Reglas para que no se repita.
  • Se hace un cambio significativo al MAPA — nueva funcionalidad, cambio en la estructura de datos, etc.
📌 Para sesiones de Claude / Cowork

Si estás trabajando con estos archivos desde una sesión nueva: lee este documento completo antes de hacer cambios. Si tu trabajo modifica algo de lo documentado aquí, actualiza este LEEME antes de terminar. El usuario confía en que este documento refleja el estado real de los archivos.

🛑 Qué no tocar

  • No renombres ni muevas la carpeta Books/ ni sus subcarpetas de autor — el MAPA tiene las rutas exactas.
  • Los respaldos van en backups/ — máximo 4 por documento, al crear un quinto se borra el más antiguo.
  • Si agregas libros nuevos a Books/, el MAPA no los detecta automáticamente — hay que agregarlos al array const books = [...] dentro del HTML.
  • Si mueves todo a otra máquina que no sea Mac/iCloud, actualiza la ruta con el botón 📂.

🔧 Arquitectura técnica del MAPA

El MAPA es un solo archivo HTML (~1.3 MB) con CSS, JavaScript, y todos los datos embebidos. No hay servidor, no hay base de datos. Todo corre en el navegador.

Estructura de datos

Los libros están en un array const books = [...] que empieza alrededor de la línea 2710. Son 219 objetos con estas propiedades: id, estante, coverId, filePath, title, author, year, desc, tesis, ideas, contexto, porqueLeer, conexiones, tags, quotes. Hay dos formatos coexistiendo: 210 libros en formato expandido (multi-línea, una propiedad por línea) y 9 en formato compacto (todo en una línea). Cualquier script que modifique el array debe detectar ambos.

Las citas con link a página exacta viven en QUOTE_PAGES (línea ~2685), con la clave "bookId::quoteIndex" y el valor es el número de página física del PDF.

Funciones clave

getQuotePageLink(book, quoteText, quoteIndex) — Genera el link "📄 Ver en PDF" para una cita. Recibe el libro, el texto de la cita, y opcionalmente el índice. Si no recibe índice explícito, busca el texto en book.quotes para encontrarlo. Devuelve cadena vacía en móvil o si no hay entrada en QUOTE_PAGES.

getFileButtonHTML(book) — Genera el botón "📂 Abrir archivo". Devuelve cadena vacía en móvil.

normalizeSearch(str) — Quita acentos para búsqueda: normaliza a NFD y elimina caracteres combinantes. Así "mexico" encuentra "México".

IS_MOBILE — Variable global que detecta Android, iOS, Huawei, HarmonyOS, o ancho ≤768px. Controla qué elementos se muestran.

Las 4 vistas principales

El MAPA tiene 4 vistas: Estantes (libros agrupados por tema), Explorador (detalle de un libro con citas y conexiones), Línea de tiempo (cronología con citas destacadas), y Atlas de conceptos (mapa visual de ideas con citas aleatorias). Cada una llama a getQuotePageLink de manera diferente — en Estantes pasa índice 0, en Explorador pasa el idx del map, y en Atlas/Timeline pasa solo el texto para que la función busque el índice.

📖 Cómo agregar un libro nuevo

Paso a paso para no romper nada:

1. Preparar el archivo

Pon el PDF o EPUB en Books/, dentro de una subcarpeta del autor (ej: Books/Marx/Nuevo-Libro.pdf). Si el autor ya tiene carpeta, úsala. Si no, crea una con el formato Nombre-Apellido.

2. Decidir el formato

Usa el formato expandido (multi-línea) — es el estándar y el más legible. El formato compacto existe por herencia pero no se recomienda para libros nuevos. Ejemplo mínimo:

{ id: "miid", estante: "mexico-profundo", // o: transformaciones, economia-poder, fundamentos, revoluciones, filosofia coverId: "miid", filePath: "Autor/Archivo.pdf", title: "Título del Libro", author: "Nombre del Autor", year: "2020", desc: "Descripción breve del libro.", tesis: "Tesis principal.", ideas: ["Idea 1", "Idea 2", "Idea 3"], contexto: "Contexto histórico.", porqueLeer: "Por qué importa este libro.", conexiones: ["otroid1", "otroid2"], tags: ["tag1", "tag2"], quotes: [ { text: "Texto exacto de la cita tal cual aparece en el PDF.", page: "p.45" } ] }

3. Agregar al array books

Busca const books = [ en el HTML (~línea 2710). Agrega el objeto nuevo al final, antes del cierre ];. No olvides la coma después del libro anterior. El id debe ser único — usa minúsculas sin espacios ni acentos (ej: "dusseletica", "marxcapital1").

4. Agregar entrada a QUOTE_PAGES (opcional pero recomendado)

Si el libro tiene citas y el PDF tiene texto extraíble, busca la cita en el PDF para obtener la página física. Agrega al objeto QUOTE_PAGES (línea ~2685):

// formato: "bookId::quoteIndex": páginaFísicaDelPDF "miid::0": 45, // primera cita del libro, página 45 "miid::1": 112 // segunda cita, página 112

5. Validar

Extraer el bloque <script> y correr node --check. Si falla, hay un error de sintaxis — revisar comas, comillas, y llaves. Este paso es obligatorio antes de guardar.

📝 Cómo agregar o verificar citas

La calidad de las citas es lo más importante. Estas son las lecciones aprendidas:

Extraer texto del PDF

Usar pdfplumber (Python) para extraer texto. Ejemplo:

import pdfplumber with pdfplumber.open("Books/Autor/Libro.pdf") as pdf: for i, page in enumerate(pdf.pages): text = page.extract_text() if text and "fragmento de la cita" in text: print(f"Página {i+1}: encontrado")

El número de página en QUOTE_PAGES es la página física del PDF (la que muestra el lector), no la numeración impresa del libro. pdfplumber empieza en 0, así que page[41] corresponde a la página 42 del PDF.

Criterios de calidad para citas

Una buena cita cumple todos estos criterios:

  • Es una oración o párrafo completo con sentido propio (no un fragmento cortado).
  • Expresa una idea sustancial del libro — no es un encabezado, título de capítulo, dato bibliográfico, ni dedicatoria.
  • Tiene entre 20 y 200 palabras aproximadamente — ni tan corta que no diga nada, ni tan larga que abrume.
  • Es legible (no es OCR basura con caracteres rotos).
  • No es una cita que el autor hace de otro autor (a menos que sea particularmente notable).

Errores comunes que evitar

  • Citas del índice o tabla de contenido — parecen texto pero son solo encabezados con números de página.
  • Información editorial — "Primera edición, 1975. ISBN..." no es una cita.
  • Texto garbled de OCR — si ves "lvi est0 es un t3xto", el PDF es imagen y no sirve para extraer citas automáticamente.
  • Páginas estimadas — nunca calcular la página por offset. Los PDFs tienen portadas, prólogos, páginas en blanco. Siempre buscar el texto exacto.
  • Comillas dentro de la cita — si la cita contiene comillas dobles ("), hay que escaparlas en el JS como \", o usar comillas simples en el string del array.

PDFs escaneados (imágenes)

Algunos PDFs son imágenes sin texto extraíble. pdfplumber devolverá cadenas vacías o basura. Para estos libros, las citas se pueden agregar manualmente (copiando del libro físico o de otra fuente verificada), pero no se agrega entrada a QUOTE_PAGES — el link "Ver en PDF" no serviría porque el visor no puede navegar a texto dentro de una imagen.
